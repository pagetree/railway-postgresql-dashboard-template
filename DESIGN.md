# Postgres Observer design direction

Reading this as an operational database console for Railway users, with a precise financial interface language.

Dial: ENERGY 2 / RHYTHM 2 / MOTION 1

## Climate

This is for developers checking production health under time pressure. It should feel controlled, exact, and trustworthy within five seconds. The interface refuses decorative terminal styling, generic dark technology chrome, and charts without an operational question.

## Decisions

Color: violet is used as one deliberate focal accent because it connects the product to Railway while leaving status colors unambiguous.

Layout: the hierarchy starts with source health and current allocation because those values decide whether the user investigates further.

Typography: Instrument Sans provides compact financial clarity, while IBM Plex Mono is reserved for machine identifiers and SQL.

Spacing: a dense but breathable rhythm supports frequent operational use without turning the dashboard into a wall of cards.

Cards: cards group one operational question at a time, while long datasets remain tables to preserve scan speed.

Charts: charts only answer resource questions across time, with limits shown beside use where Railway supplies both.

Motion: interaction feedback only, because continuous animation would distract from changing telemetry.

Theme: light is the default for long sessions, with a complete dark option for operations in low light.

Identity motif: a compact violet P mark and sharp violet chart line connect navigation, focus, and telemetry without coating the entire interface in brand color.
